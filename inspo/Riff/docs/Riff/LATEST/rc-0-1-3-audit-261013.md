# Riff 0.1.3-rc — audit corrections and delivery

This is dated implementation and verification evidence, not an additional behavior contract. The
user authorized the audit corrections, documentation reconciliation, 0.1.3-rc version, commit/push
and installation on phone and HU.

## Implemented corrections

1. **Collision acquisition:** one guarded acquisition boundary now covers initial metadata and
   deferred Media.ID collision/fallback reads. Checkpoints retain newly discovered FAILEDL1
   observations in the working set; prepared results cannot resurrect them. Journal/control failures
   abort the pass instead of being mistaken for failed media. See
   [source failures](/Riff/LATEST/indexer-source-failures).
2. **Artwork cancellation:** slow provider cancellation is dispatched through a bounded canceller
   rather than invoked under the artwork-owner lock. Queue start and transitions do not wait for
   image-provider cancellation. Existing timeout, cache, stale-result and bounded retry policy
   remains under the [artwork owner](/Riff/LATEST/ui-foundation#physical-ui-and-artwork).
3. **Profile commands:** deferred reactions, AI/manual/bookmark queue commands and associated
   completions retain their originating store, profile and epoch. Serialized profile work and
   transactional admission reject stale queue activation after a profile switch. See
   [queue commands](/Riff/LATEST/player-queues).
4. **Long source identifiers:** the shared Android source-key constructor hashes the complete exact
   document URI into a fixed-width XXH3 field; long Unicode names no longer overflow the bounded RAM
   journal protocol. Names remain display data. See
   [reliable IPC](/Riff/LATEST/reliable-player-indexer-ipc).
5. **Partial album positions:** partial Disc/Track/total evidence joins a complete position only
   when there is one compatible maximal class. Missing fields cannot bridge declared repeats or
   conflicting positions. The chosen factual carrier preserves known position evidence without
   inventing tags. See [position owner](/Riff/LATEST/album-grouping-positions).
6. **Artwork after generation changes:** selecting an occurrence re-requests its exact resolved
   binding at the current library generation, including an already buffered next track. Empty
   selection and stale completion are guarded.
7. **Failed physical source opens:** a shared datasource retries remaining physical bindings after
   an IOException from opening a candidate and commits the chosen binding only after success.
   Exhaustion, repeated candidates and queue replacement are bounded. This does not promise failover
   after decoder consumption has begun.

Focused consolidation shares SAF path traversal between URI/artwork resolution, acquisition
guarding, source-key construction and profile-command context. Catalog construction reuses common
album-position evidence and indexed membership lookups. Accepted library cohorts reuse prepared
models while still resolving current grants. No broad mechanical file split or unmeasured
performance claim is part of this delivery.

The acquisition API documentation now describes the implemented optional revision check. Current
status separates installed APKs from the independently published website. The
[architecture map](/Riff/LATEST/architecture-decisions) routes these decisions to their owners.

## Working-device verification

The same signed APK is installed on phone and HU. Installed bytes, certificate continuity, package
UID, first-install time and exact persisted SAF grants were compared before and after installation.
The phone retains two grants and HU one. Player backups remain private.

Actual Album Play, two visible FWD taps and a genuine automatic transition after a normal near-end
seek pass on both devices. The newly selected queue reached PLAYING after its loading state:

| Device role | Queue PLAYING observed | First FWD | Second FWD |
| ----------- | ---------------------: | --------: | ---------: |
| Phone       |                 699 ms |    532 ms |     591 ms |
| HU          |                 852 ms |    635 ms |     623 ms |

These are bounded command-to-observed MediaSession readiness samples obtained by coarse ADB polling.
An initial sample from the old phone queue is excluded. They are neither physical speaker-output
latency nor a controlled same-media benchmark. Once the seek settled, both automatic transitions
changed occurrence while remaining PLAYING without an observed new buffering event. No fatal
exception, ANR, out-of-memory or playback-error marker was found in these smoke-run logs. Both
devices were left paused.

Phone reconnection was necessary before installation; that transport interruption is not an
application failure. This delivery does not claim exhaustive absence of defects, long-running
indexing throughput, universal provider behavior or supported vehicle-host certification.
